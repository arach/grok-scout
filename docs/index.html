Grok host integration

Scout coordination for Grok.

MCP packaging that gives Grok Bot and Grok agents project-routed Scout asks, direct messages, and durable broker-backed follow-up — the same local broker as every other Scout host.

install
$ git clone https://github.com/arach/grok-scout
$ cd grok-scout
$ bun run install:global
# Grok Bot / Cursor launches scout mcp as a local stdio server

Tools

Scout MCP for Grok.

Grok Scout points Grok Bot (and Cursor-hosted Grok agents) at OpenScout's canonical MCP server instead of introducing a second broker. Fresh work should use projectPath + harness so the broker chooses the worker. Grok is also a first-class Scout harness — this package is the host bridge so Grok can talk to the broker, not only be launched by it.

messages_send

Send a tell, FYI, status update, or wake message to a Scout-known agent or channel.

ask

Ask by project/capability first, then return durable ref, conversation, message, flight, and work handles.

agents_search

Discover routable Scout agents only when a specific target is unknown or ambiguous.

How it works

The host launches scout mcp.

The integration stays host-specific and small. Scout owns broker state, routing, returned handles, and agent identity.

01

The installer updates MCP config

scripts/install.mjs writes the scout entry into ~/.cursor/mcp.json or a project .cursor/mcp.json (the path Grok Bot and Cursor share today).

02

The host starts the local Scout MCP server

The MCP entry launches scout mcp --context-root ${workspaceFolder} over stdio.

03

Routing stays structured

Use explicit tool fields such as targetLabel, targetAgentId, and channel. Message body text stays payload, not hidden routing metadata.

Requirements

What you need.

  • Grok Bot, Cursor, or another host that reads Cursor-style mcp.json
  • OpenScout installed and set up locally
  • A running Scout broker
  • scout on PATH, or Bun available for bunx @openscout/scout
